# 需求与范围

这份文档把最初的《开发任务书》展开成可验收的条目，并明确**不做什么**。
范围之外的东西不是遗漏，是刻意排除的（理由见 `00-决策记录.md`）。

---

## 1. 起点

服务器上原本跑着 AstrBot + SnowLuma 两个进程，已能正常收发 QQ 消息。
问题只有一个：**在 1 核 2G 上内存占用过高**。

需求原文：「单独将运行 QQ 机器人所依赖的功能进行最小限度的保留，移除其他不需要的功能，做个整合。」

## 2. 硬约束

| 约束 | 值 | 来源 |
| --- | --- | --- |
| CPU | 1 核 | 不可升配 |
| 内存 | 2 GB | 不可升配 |
| 磁盘 | 约 14 GB 可用 | 现有 VPS |
| 部署形态 | Docker（compose） | 任务书 |
| 一键命令长度 | 一条，不能是一长串参数 | 任务书 |
| 部署前检测 | 检测 Docker，没有则询问是否安装 | 任务书 |
| 服务器现状 | 全新，无历史数据 | 用户确认 |
| 同机还有 | 1Panel（用户先装，本项目后装） | 用户确认 |

## 3. 功能范围

### 3.1 必须有

**协议接入**
- 通过 OneBot v11 正向 WebSocket 连接 NapCat。
- 断线自动重连，退避重试，不影响面板可用性。
- 启动后自动拉取机器人账号信息（QQ 号、昵称）。

**消息处理**
- 群聊：仅在被 @ 时响应。
- 私聊：直接响应。
- 去重：同一条消息重复推送只处理一次（按 `message_id`）。
- 上下文：按会话累积最近若干轮，超出窗口丢弃最早的。
- 输出清洗：模型回复里的 Markdown 标记要剥掉（QQ 不渲染）。
- 长回复分段发送，避免超出单条消息长度限制。
- 模型调用失败时发一条兜底回复，而不是沉默。

**触发控制**
- 唤醒词：消息里出现指定词也能触发（不限于 @）。
- 用户冷却：同一用户短时间内只回一次。
- 被动回复概率：按概率决定回不回，避免刷屏。
- 黑名单用户、白名单群（白名单非空时只服务名单内的群）。

**模型**
- OpenAI 兼容接口，可配 base URL / API Key / 模型名。
- 支持流式输出。
- 思考模式可开关；开启时温度参数不生效（DeepSeek 的约束）。
- 记录 token 用量与估算费用。

**面板**
- 登录（密码，可选 TOTP 二次验证）。
- 概览：连接状态、今日消息数、token 用量、费用。
- 设置：模型、触发规则、黑白名单。
- 人格：增删改，切换生效。
- 会话：列表、查看历史消息、清空。
- 用量：按日统计。
- 实时日志：SSE 推送。
- 测试发送：在面板里直接发一条消息，验证链路。

**部署与运维**
- `sudo ./install.sh` 一条命令完成：环境检查 → Docker → 配置与密钥 → 构建 → 启动 → 健康检查。
- `qqbot` 命令：`status` / `logs` / `up` / `down` / `restart` / `upgrade` / `rollback` / `backup` / `restore` / `tunnel` / `uninstall`。

### 3.2 明确不做

| 不做 | 理由 |
| --- | --- |
| 域名、证书、反向代理 | 用户自己负责（见 ADR-010） |
| 插件系统 / 多平台适配 | 与"最小化"直接冲突（见 ADR-001） |
| 图片、语音、视频消息处理 | 需求没提，且会显著增加依赖与内存 |
| 多用户 / 多机器人实例 | 单租户单实例，多实例请开多台机器 |
| 群管理（禁言、踢人、审批） | 与"聊天机器人"这个定位无关 |
| 数据看板 / 复杂图表 | 面板只做够用的程度 |

## 4. 非功能要求

| 项 | 目标 |
| --- | --- |
| qqbot 容器常驻内存 | ≤ 100 MB（`mem_limit` 设 256m 留余量） |
| 两个容器合计 | ≤ 1.25 GB（给系统与 1Panel 留 700 MB） |
| 冷启动到面板可访问 | ≤ 5 秒 |
| 首次完整安装（含拉镜像） | ≤ 20 分钟 |
| 二进制体积 | ≤ 20 MB（单文件，含前端） |
| 依赖数量 | 三个：TOML 解析、SQLite 驱动、无其他框架 |
| 数据安全 | API Key 加密落库，密钥与库分离存放 |
| 默认暴露面 | 仅 127.0.0.1，公网不可达 |

## 5. 验收方式

见 `05-验收.md`。核心原则：**每一条都在真实服务器上跑过**，不是"代码写完了"就算完成。

## 6. 已知风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| QQ 账号被风控 | 机器人掉线 | 与 NapCat 方案同源，用户已知悉并接受（ADR-002） |
| NapCat 升级改配置格式 | 登录态失效 | 数据卷固定挂载，升级只换镜像 tag |
| 2G 内存构建时 OOM | 安装中断 | 安装脚本检测内存并提示加 swap |
| DeepSeek 峰谷定价 | 费用波动 | 用量页按实际 token 记账，不做预测 |
