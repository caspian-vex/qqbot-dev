# 部署手册（换一台新服务器）

这份文档假设你手上是一台**全新的、干净的**服务器，从零把机器人跑起来。
已经装好的机器日常运维看 `README.md` 的运维命令一节。

---

## 0. 前置条件

| 项 | 要求 | 怎么查 |
| --- | --- | --- |
| 架构 | x86_64 / arm64 | `uname -m` |
| 内存 | ≥ 1.8 GB（2G 是设计基准） | `free -m` |
| 磁盘 | ≥ 8 GB 可用 | `df -h /` |
| 系统 | Debian 12+ / Ubuntu 22.04+（能跑 `get.docker.com`） | `cat /etc/os-release` |
| 权限 | root | `id -u` 输出 0 |
| 网络 | 能访问 github.com、docker hub、api.deepseek.com | — |

内存不足 1.8G 时 `install.sh` 会警告并询问是否继续。低于 1.5G 基本不要试，
构建镜像阶段会被 OOM 杀掉。

**建议先加 2G swap**（1 核 2G 机器构建镜像时的兜底）：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## 1. 第 0 步：确认代码已经推送到仓库

**这一步最容易漏。** 项目代码必须在 GitHub 上，否则新机器 clone 下来是空的。

在你**本地开发机**上：

```bash
cd /path/to/qqbot-dev
git status                     # 确认改动都已提交
git add -A && git commit -m "..."   # 有未提交的就先提交
git push origin main
```

验证：

```bash
git ls-tree -r --name-only HEAD | head
```

应该能看到 `install.sh`、`go.mod`、`internal/`、`web/dist/` 等文件。
如果只看到 `.gitignore`，说明代码根本没推上去。

> **`web/dist/` 必须在仓库里。** 前端是手写的静态文件，没有构建步骤，
> 靠 `//go:embed` 打进二进制。被 gitignore 掉会导致 clone 后编译失败，
> 报错是 `pattern all:dist: no matching files found`。

## 2. 装 1Panel（可选，但要装就先装）

如果这台机器还要用 1Panel 管面板和 Docker，**先装 1Panel，再装本项目**。

理由：1Panel 安装时会把 Docker 一起装好。本项目 `install.sh` 检测到 Docker 已存在
就直接复用，不会重复安装，也不会跟 1Panel 抢。

本项目跟 1Panel 的兼容性：

- 不改 `/etc/docker/daemon.json`（日志轮转写在 compose 的服务级配置里）
- 不用 `network_mode: host`
- 容器名固定为 `qqbot-core` / `qqbot-napcat`，compose 项目名 `qqbot`，不会撞名

装完 1Panel 后继续往下走，`install.sh` 会说 `✓ docker 已安装`。

## 3. 装本项目

### 3.1 拉代码

干净的 Debian / Ubuntu 最小安装**没有 git**，先装：

```bash
apt-get update && apt-get install -y git
```

然后拉代码（仓库是公开的，不需要凭据）：

```bash
git clone https://github.com/caspian-vex/qqbot-dev.git
cd qqbot-dev
```

拉完先确认三件事，不满足就别往下走：

```bash
ls -l install.sh                       # 必须有 x 位：-rwxr-xr-x
head -1 install.sh | od -c | head -1   # 结尾必须是 \n，不能出现 \r
ls web/dist/                           # 必须有 app.js index.html style.css
```

这三条对应三个曾经踩过的坑：

- **没有 x 位** → `sudo ./install.sh` 报 `Permission denied`。
  Windows 上 `chmod +x` 不会进仓库（`core.fileMode=false`），
  仓库里已经用 `git update-index --chmod=+x` 修正过；万一还是 644，补一句
  `chmod +x install.sh deploy/qqbotctl` 即可。
- **出现 `\r`** → `bash install.sh` 报 `bad interpreter: /usr/bin/env bash^M`。
  仓库里有 `.gitattributes` 钉死 `eol=lf`，正常不会发生。
- **缺 `web/dist/`** → 编译报 `pattern all:dist: no matching files found`。
  它是前端源码（手写原生 JS），靠 `//go:embed` 打进二进制，必须在仓库里。

### 3.2 一条命令安装

```bash
sudo ./install.sh
```

它会依次做：

1. 预检架构 / 内存 / 磁盘 / swap
2. 检测 Docker，没有就问你要不要装（`get.docker.com` 官方脚本）
3. 生成密钥 `etc/env`（0600）与引导配置 `etc/qqbot.toml`
4. 构建镜像、启动容器、等面板健康
5. 把 `qqbot` 命令装到 `/usr/local/bin`

首次安装约 **5 分钟**（要下 Go 镜像、NapCat 镜像 2.16G）。

常用变体：

```bash
sudo ./install.sh --yes                    # 全程不询问
sudo ./install.sh --panel-bind 127.0.0.1   # 面板只允许本机（配合隧道或反代）
sudo ./install.sh --dir /srv/qqbot         # 换安装目录
```

> 默认面板绑 `0.0.0.0`，装完直接访问 `http://<服务器IP>:8080`，不需要 SSH 隧道。
> 安全边界靠面板自己的认证：32 位随机密码 + 5 次失败锁定 + 可选 TOTP。
> 想改回只允许本机就加 `--panel-bind 127.0.0.1`。

### 3.3 记下三样东西

安装结束会打印：

```
面板地址     http://<服务器IP>:8080
面板账号     admin / <32位密码>
NapCat WebUI http://<服务器IP>:6099/webui
WebUI Token  <32位>
```

**面板密码只打印这一次**（存在 SQLite 里，哈希后无法再取）。
如果没记下来，见第 6 节的重置办法。

## 4. 上线：扫码 + 填 Key

### 4.1 放行端口（最容易漏的一步）

云服务器的安全组 / 防火墙默认是关的。不放行就是「装完了但打不开」，
而且浏览器只会显示「无法连接」，不会告诉你原因。

| 端口 | 用途 | 是否必须 |
| --- | --- | --- |
| 8080 | 面板 | 是 |
| 6099 | NapCat WebUI（扫码） | 是 |
| 3001 | OneBot WS | **不要放行** |

在云厂商控制台的「安全组 / 防火墙」里加两条 TCP 入站规则。
机器上装了 ufw 的话：

```bash
ufw allow 8080/tcp && ufw allow 6099/tcp
```

> 3001 不能放行。它默认没有 Token，一旦公网可达，任何人连上来就能冒充机器人发消息。
> 这个端口在 `compose.yaml` 里写死绑 `127.0.0.1`，不要改。

### 4.2 扫码登录 QQ

浏览器打开 `http://<服务器IP>:6099/webui`，Token 用安装结束打印的那个。

用要当机器人的 QQ 号扫码。登录成功后：

```bash
qqbot logs -f
# 5 秒内应看到「已登录」和 QQ 号、昵称
```

### 4.3 确认 WebSocket 服务端

NapCat 的「网络配置」里应该已经有一条 **WebSocket 服务端**，端口 `3001`，**Token 留空**。

- Token 留空是刻意的：`MODE=ws` 初始化时 NapCat 不生成 token，
  这里填了值反而会让 qqbot 握手 401，连不上（见 ADR-011）。
- 3001 只绑 `127.0.0.1`，外部拿不到，留空是可接受的默认姿态。

### 4.4 填模型 Key

浏览器打开 `http://<服务器IP>:8080`，用 `admin` + 安装时打印的密码登录。

进「设置」页：

| 项 | 值 |
| --- | --- |
| 模型地址 | `https://api.deepseek.com`（默认已填） |
| 模型名称 | `deepseek-flash`（默认已填） |
| API Key | 你的 DeepSeek Key |
| 思考模式 | 默认关闭。开启后温度参数不生效（DeepSeek 的限制） |

保存后去「人格」页确认当前人格是 `default`，提示词是 `You are a helpful assistant`。

### 4.5 验证

在群里 @ 机器人说一句话，或者用面板「测试发送」直接发一条。

## 5. 从旧机器迁移（不是全新装）

如果你已经有机器人在跑，想把数据搬到新机器，**顺序很重要**。

### 5.1 旧机器上备份

```bash
qqbot backup
# → /opt/qqbot/backup/qqbot-20261027-095142.tar.gz
```

这个包里有：`data/qqbot/qqbot.db`（会话、用量、设置）、`etc/qqbot.toml`、`etc/env`（密钥）。

**`etc/env` 里的 `QQBOT_SECRET_KEY` 必须一起搬。** 它是加密 LLM API Key 的主密钥，
丢了就等于所有 Key 都要重新录（数据库里的密文再也解不开）。

### 5.2 旧机器上单独搬 NapCat 登录态（可选）

`qqbot backup` **不含** NapCat 的 QQ 登录态。想免扫码就手动搬：

```bash
tar czf /root/napcat-state.tar.gz -C /opt/qqbot data/napcat
```

不搬也可以，新机器扫码重新登录一次即可（推荐，更干净）。

### 5.3 新机器上装好后恢复

先按第 3 节装完（**不要扫码、不要配任何东西**），然后：

```bash
scp root@<旧IP>:/opt/qqbot/backup/qqbot-*.tar.gz /root/
qqbot restore /root/qqbot-20261027-095142.tar.gz
```

`restore` 会：停容器 → 解包覆盖 `data/` 与 `etc/` → 重新对齐文件属主 → 启动。

恢复后**面板密码和 API Key 都沿用旧的**，不需要重新配。

如果同时搬了 NapCat 登录态：

```bash
scp root@<旧IP>:/root/napcat-state.tar.gz /root/
qqbot down
tar xzf /root/napcat-state.tar.gz -C /opt/qqbot
chown -R 1000:1000 /opt/qqbot/data/napcat
qqbot up
```

### 5.4 迁移后的检查

```bash
qqbot status          # 两个容器 Up，面板健康
qqbot logs -f         # 看到「已登录」
```

确认没问题再停旧机器，**别提前关**——万一新机器有问题还能退回去。

## 6. 常见问题

### 面板密码没记下来

密码是 argon2id 哈希存的，取不回明文。办法是清掉密码字段让它重新生成：

```bash
qqbot down
docker run --rm -v /opt/qqbot/data/qqbot:/d alpine \
  sh -c 'apk add -q sqlite && sqlite3 /d/qqbot.db \
  "UPDATE settings SET value=json_set(value, \"\$.panel.password_hash\", \"\") WHERE key=\"settings\";"'
qqbot up
qqbot logs qqbot | grep -A3 面板初始凭据
```

> 表结构如果变了（`settings` 表的列名），先 `sqlite3 qqbot.db ".schema settings"` 看一眼。
> 更稳的做法是直接 `qqbot uninstall --purge` 重装，代价是丢掉会话历史。

### 面板打不开

按这个顺序查，多数情况是第一条：

```bash
# 1) 服务端自己通不通（排除面板本身的问题）
curl -s localhost:8080/healthz
```

- 本机通、外面不通 → **安全组 / 防火墙没放行 8080**（见 4.1）
- 本机也不通 → 继续往下看
- 容器 `Exited` → `qqbot logs qqbot` 看退出原因
- 容器活着但端口没监听 → `docker ps` 看 PORTS 列，确认是 `0.0.0.0:8080->8080/tcp`
  而不是 `127.0.0.1:8080`（后者说明 `PANEL_BIND` 还是本机绑定）

想把面板改回只允许本机（改完配隧道或反代）：

```bash
sudo ./install.sh --panel-bind 127.0.0.1
```

反过来，从只允许本机改成公网可达：

```bash
sudo ./install.sh --panel-bind 0.0.0.0
```

两种都只改 `etc/env` 里的 `PANEL_BIND` 并重建容器，数据不动。

### 想确认 3001 没有暴露

```bash
docker ps --format '{{.Names}}\t{{.Ports}}' | grep 3001
# 必须是 127.0.0.1:3001->3001/tcp，出现 0.0.0.0 就说明被人改过
```

从外部验证（在你自己电脑上，注意别被本地代理干扰）：

```bash
curl --noproxy '*' -m 5 http://<服务器IP>:3001/
# 期望：连接失败。如果返回任何 HTTP 状态码，说明端口真的暴露了，立刻改回去。
```

### 机器人不回消息

按顺序排查：

1. `qqbot logs -f` 有没有「已登录」
2. 没登录 → NapCat WebUI 扫码
3. 登录了但 `连接断开` → NapCat 的 WebSocket 服务端没开，或 Token 不一致
4. 连上了但不回 → 面板「概览」看最后事件时间；群聊要 @ 才触发
5. 触发了但没回复 → 看日志里的模型错误，多半是 API Key 或余额

### 构建时被 OOM 杀掉

1 核 2G 构建镜像内存会顶到上限。先加 swap（见第 0 节），再 `qqbot upgrade`。

### 换镜像 tag / 回滚

```bash
qqbot rollback 20261027-0941    # 换回旧版本镜像
qqbot upgrade --src /root/qqbot-dev   # 从新源码重建
```

## 7. 装完之后

| 事项 | 命令 / 位置 |
| --- | --- |
| 看资源占用 | `qqbot status` |
| 定期备份 | `qqbot backup`（只留最近 7 份） |
| 备份挪到别处 | 从 `/opt/qqbot/backup/` 拉走 |
| 改监听地址 | 改 `/opt/qqbot/etc/env` 的 `PANEL_BIND`，然后 `qqbot restart` |
| 改协议端地址 | 改 `/opt/qqbot/etc/qqbot.toml`，然后 `qqbot restart` |
| 改模型 / 人格 / 触发规则 | 面板里改，立即生效，不用重启 |
