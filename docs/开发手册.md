## 1. 一页架构

```
QQ 客户端
   │  (QQ 协议，加密)
   ▼
NapCat 容器（qqbot-napcat）           mlikiowa/napcat-docker
   │  OneBot v11 正向 WebSocket，ws://napcat:3001
   ▼
qqbot 容器（qqbot-core）              单二进制，非 root(10001)，alpine
   ├─ internal/onebot   连协议端、收发报文、断线重连
   ├─ internal/bot      要不要回 → 排队 → 组装上下文 → 调模型 → 分段发回
   ├─ internal/panel    HTTP 面板（5333），自己服务前端静态文件
   └─ internal/store    SQLite（/opt/qqbot/data/qqbot/qqbot.db）
```

两个容器都在 `deploy/compose.yaml` 里，`mem_limit` 合计 1.25G。
面板不是独立进程，就是 qqbot 自己的一个 `http.Server`。

## 2. 目录与包职责

| 路径 | 职责 | 备注 |
| --- | --- | --- |
| `cmd/qqbot/` | 容器入口。`run` / `status` / `doctor` / `reset-password` / `version` | 装配所有组件，前台运行 |
| `cmd/mockonebot/` | 本地联调用的假 NapCat + 假模型 + 调试页 | 只有开发用，不进镜像 |
| `internal/onebot/` | OneBot v11 客户端：连接、重连、API 调用、事件解析 | `client.go` `actions.go` `types.go` |
| `internal/bot/` | 消息引擎：触发判定、去重、冷却、队列、上下文、投递 | 核心逻辑都在这 |
| `internal/ctxmgr/` | 按 token 预算裁剪历史，保证 user/assistant 成对 | 见 §4.3 |
| `internal/llm/` | OpenAI 兼容 Chat Completions 客户端，SSE 流式 | 显式关思考模式 |
| `internal/panel/` | 面板 HTTP 服务：认证、API、SSE 日志 | `api.go` 是路由与处理器 |
| `internal/store/` | SQLite 访问层，手写迁移 | 纯 Go 驱动，无 CGO |
| `internal/persona/` | 人格提示词模板与变量展开 | `{{.BotName}}` 之类 |
| `internal/secret/` | AES-GCM 加解密，用于 API Key 与 TOTP Secret | 主密钥在 `etc/env` |
| `internal/config/` | 引导配置（TOML）+ 密钥文件加载 | 与 store 的设置分开，见 §4.1 |
| `internal/mock/` | 假协议端、假模型、集成测试 | 被测的是真实代码路径 |
| `web/dist/` | 前端源码（手写原生 JS/CSS/HTML） | **是源码不是产物**，必须进 git |
| `web/embed.go` | `//go:embed all:dist` | 缺了 dist 编译直接失败 |
| `deploy/` | `compose.yaml`、`qqbot.toml` 模板、`qqbotctl` 运维命令 | 安装时拷到 `/opt/qqbot` |
| `install.sh` | 服务器一键安装 | 见 §8 |

依赖只有四个：`BurntSushi/toml`、`modernc.org/sqlite`、`gorilla/websocket`、`golang.org/x/crypto`。
没有 Web 框架、没有 ORM、没有日志库（用 `log/slog`）。

## 3. 一条消息的完整路径

想改行为，先知道改哪一段。

```
onebot.Client.Run          ← WebSocket 收到事件帧
  └─ Engine.HandleEvent    ← 按 post_type 分发
      └─ handleMessage     internal/bot/bot.go
          1. 忽略自己发的（防止自问自答）
          2. dedupe.Seen(message_id)      5 分钟窗口，重复推送只处理一次
          3. store.Settings()             读运行期设置
          4. decide(ev, settings)         → 触发判定，见 §4.4
          5. queue.Submit(sessionKey, …)  同会话串行，跨会话并发（默认 3）
              └─ reply()
                  6. 取当前人格 → persona.Build（展开变量）
                  7. ctxmgr.Build            按预算裁剪历史
                  8. llm.Chat                SSE 流式，记首字延迟
                  9. StripMarkdown           剥掉 QQ 不渲染的标记
                 10. 先落库再发送             发送失败也不破坏上下文连贯性
                 11. Split(reply, 120 rune) 长回复分段
                 12. sendText                第一段带引用/@，段间隔 300-800ms 随机
```

几个刻意的顺序：

- **先落库再发送**：发送失败时上下文仍然连贯，用户重发不会看到"模型失忆"。
- **判断顺序固定**：黑名单 → 私聊 → 群白名单 → @ → 唤醒词 → 被动概率。
  白名单/黑名单永远优先于概率，不会出现"在黑名单里但随机命中被回复"。
- **模型失败发兜底**：`sendFallback` 说一句"卡住了"，不沉默。兜底本身失败就放弃，不重试，
  避免故障时放大流量。

## 4. 关键设计约束

### 4.1 配置分两层（ADR-005）

| 层 | 位置 | 谁写 | 内容 |
| --- | --- | --- | --- |
| 引导配置 | `/opt/qqbot/etc/qqbot.toml` | 安装脚本生成，人工可改，**面板不写** | 数据目录、日志、OneBot 地址、面板监听 |
| 运行期设置 | SQLite `app_settings`（单行 JSON） | 面板写，热生效 | 模型、人格、触发规则、面板凭据 |

分开的原因：面板若也写 TOML，注释和人工改动会被冲掉，并发写还有竞态。

### 4.2 密钥（ADR-008）

- 主密钥 `QQBOT_SECRET_KEY`（64 位十六进制）加密 LLM API Key 与 TOTP Secret，落库时带 `enc:` 前缀。
- 密钥与数据库**分开存放**：密钥在 `etc/env`，密文在 `data/qqbot/qqbot.db`。
  单拿数据库解不开 Key；单拿密钥没有密文也没用。
- 二进制读的是 `etc/secrets.env`（`config.SecretsPath()`），但 `install.sh` 只写 `etc/env`，
  由 compose 的 `env_file` 注入成环境变量——`LoadSecrets` 里环境变量优先，所以两条路都通。
  **别把这两条路混着用**：改了 `secrets.env` 却发现没生效，先看环境变量。
- `QQBOT_SECRET_KEY` 丢了 = 所有 API Key 要重新录，备份时必须一起搬。

### 4.3 上下文预算（`internal/ctxmgr`）

1. 取最近 `maxTurns * 2` 条（默认 10 轮）；
2. 预算 = `token_budget` − 系统提示 − 本轮用户消息 − 512（预留输出）；
3. 从最新往回累加，凑够就停；
4. 若起点落在 `assistant`，往前挪一条，让上下文从 `user` 开始。

第 4 步不是洁癖：上下文以 assistant 开头时，部分模型会把历史回复当成待续写内容。
token 数是估算（`llm.EstimateTokens`），真实用量优先取 API 返回的 `usage`。

### 4.4 触发判定（`internal/bot/filter.go`）

`decide()` 返回 `Decision{Respond, Reason, Text, Direct}`，`Reason` 会进 debug 日志——
排查"为什么不回"时先看这个字段，比猜快得多。

- `Direct=true`（@、唤醒词、私聊）受**用户冷却** 3 秒限制；
- `Direct=false`（被动接话）额外受**群冷却**（默认 30 秒）限制，且要过 `PassiveRate` 概率（默认 0.15）；
- 群白名单非空时，只服务名单内的群；黑名单用户直接丢弃。

### 4.5 并发模型

| 组件 | 文件 | 作用 |
| --- | --- | --- |
| `dedupe` | `internal/bot/queue.go` | 按 `message_id` 去重，5 分钟窗口，带容量上限 |
| `queue` | 同上 | 按会话串行、跨会话并发，队列满则丢弃并计 `Dropped` |
| `cooldown` | 同上 | 用户级 3 秒 / 群级 30 秒的令牌桶式冷却 |

同一会话必须串行：两条消息并发跑会各读一份历史，互相看不见对方的回复，上下文就断了。

### 4.6 分段投递

`Split()` 按 120 rune 上限切，优先在换行、句号、逗号处断，最多 `MaxSegments` 段（默认 4）。
只有第一段带引用或 @；段间 300-800ms 随机停顿，模拟打字节奏。
超长回复被截断时补 `…`，不静默丢内容。

### 4.7 日志

`slog` 双写：标准输出（docker logs 看）+ 进程内环形缓冲（500 条，面板 SSE 看）。
用 `panel.NewHubHandler` 包装基础 handler，没有引入第三方日志库。
默认级别 `warn`——低配机器上 `info` 会把云盘写爆。

### 4.8 面板认证（ADR-007）

- 密码 argon2id（64MB / 3 轮 / 2 线程，登录约 100ms，刻意不在 1 核上打满）；
- 会话 12 小时，Cookie 存 `sha256(token)`，进程内 map；
- 双提交 CSRF：`qqbot_csrf` cookie + `X-CSRF-Token` 头；
- 登录失败 **10 次**锁 **15 分钟**（内存计数，重启即清零）；
- 可选 TOTP。

路由集中在 `internal/panel/server.go` 的 `routes()`，`/api/*` 全部要认证，
写操作（`PUT`/`POST`）额外校验 CSRF。`GET /healthz` 不认证，compose 的健康检查用它。

### 4.9 数据库

单文件 SQLite，WAL 模式，手写迁移（`store.migrate()`，全是 `CREATE TABLE IF NOT EXISTS`）。

| 表 | 用途 |
| --- | --- |
| `app_settings` | 单行（`id=1`）JSON，整份运行期设置 |
| `personas` | 人格，`active` 标记当前生效 |
| `sessions` | 会话（`group:<id>` / `private:<id>`） |
| `messages` | 消息历史，按 `session_id, id` 建索引 |
| `usage_log` | 按日、按模型的 token 用量，`peak` 标记峰谷 |
| `audit_log` | 面板写操作审计 |

**改表结构**：往 `migrate()` 的 `stmts` 里加语句，别改已有语句。
`app_settings` 是整份 JSON，加字段只要给 struct 加 tag 并补默认值（`DefaultSettings`）。

## 5. 本地开发

不需要 Docker，不需要真 QQ 号。

```bash
go build ./...                  # 编译
make build                      # 出 bin/qqbot 与 bin/mockonebot
make mock                       # 起假环境（前台，占一个终端）
make dev                        # 另开一个终端，用 .devroot 跑机器人
```

`make mock` 起三个端口：

| 端口 | 角色 | 说明 |
| --- | --- | --- |
| 3001 | 假 NapCat | OneBot v11 正向 WS，报文格式与真的对齐 |
| 3010 | 假模型 | OpenAI 兼容，可配置固定回复、延迟、500 |
| 3020 | 调试页 | 浏览器打开，点按钮造消息、断连、清库 |

调试页能干的事：造一条群消息（可带/不带 @）、切私聊、断开连接、让模型返回 500、
清空记录。**不用真登 QQ 就能验证各种边界情况**，这是本地开发的主要手段。

数据落在 `$QQBOT_ROOT/data/qqbot/qqbot.db`，`make dev` 默认用 `.devroot`（已在 gitignore）。
删掉 `.devroot` 就是干净环境。

`make mock` 的 `-db` 参数会把该库里保存的模型地址指向 mock，所以面板里的 Key 随便填。

### make 目标

| 目标 | 作用 |
| --- | --- |
| `make build` | 当前平台构建到 `bin/`（含 mockonebot） |
| `make release` | 交叉编译 linux/amd64 + arm64 到 `dist/`，并生成 `checksums.txt` |
| `make test` | `go test ./...` |
| `make test-race` | `-race`，需要 gcc；没有就打印跳过提示 |
| `make test-remote` | 同步源码到服务器跑 `-race`（Windows 本地没 gcc 时用） |
| `make lint` | `go vet` + `gofmt -l`（跳过 `web/`） |
| `make mock` / `make dev` | 见上 |
| `make clean` | 删 `bin/`、`dist/`。**不删 `web/dist`**，那是源码 |

### Windows 上的两个坑

1. **没有 gcc** → `-race` 跑不了。用 `make test-remote`（需要 `QQBOT_SSH_HOST`，
   可选 `QQBOT_SSH_KEY`、`QQBOT_REMOTE_DIR`）。
2. **`chmod +x` 不进仓库**（`core.fileMode=false`）。脚本的可执行位靠
   `git update-index --chmod=+x` 显式写进 index，见 §11。

| 层 | 位置 | 覆盖什么 |
| --- | --- | --- |
| 单元 | `internal/bot/split_test.go`、`internal/onebot/types_test.go`、`internal/store/store_test.go`、`internal/panel/auth_test.go` | 分段、报文解析、存储、密码哈希与 TOTP |

失败就不出产物——宁可没有 Release，也不要发一个跑不起来的二进制。

## 7. 构建与发布

### 版本号注入

`Makefile` 用 ldflags 把三个值打进 `internal/version`：

```
VERSION    git describe --tags --always --dirty（没有标签就是 dev）
COMMIT     git rev-parse --short HEAD
BUILD_DATE UTC 时间戳
```

构建参数固定为 `CGO_ENABLED=0` + `-trimpath` + `-s -w`。**预编译产物与本地构建必须一致**，
否则两条安装路径的产物不等价（这是 ADR-015 的前提）。

### 两个 Dockerfile

| 文件 | 做什么 | 耗时 | 谁用 |
| --- | --- | --- | --- |
| `Dockerfile` | `golang:1.27-alpine` 里 `go build` | 约 90s | 源码路径、`qqbot upgrade` |
| `Dockerfile.runtime` | 只 `COPY qqbot.prebuilt` + alpine 运行段 | 约 3s | 预编译路径 |

两者运行段必须保持一致：uid 10001、`TZ=Asia/Shanghai`、`QQBOT_ROOT=/opt/qqbot`、
`EXPOSE 5333`、`ENTRYPOINT ["/usr/local/bin/qqbot"]` + `CMD ["run"]`。**改一处要改两处。**

`Dockerfile` 里 `ARG GOPROXY` 必须声明在 `go mod download` 之前，否则 compose 传的值被静默丢弃，
回落到 `proxy.golang.org`，国内直接超时。

### 发版流程

```bash
git tag v0.1.1
git push origin v0.1.1        # 触发 CI：测试 → 交叉编译 → 校验 → 发布
```

CI 会验三件事，任何一项不过就失败：

1. 两个产物都非空且**静态链接**（alpine 没有 glibc，动态链接进去直接 not found）；
2. 架构对得上（`x86-64` / `aarch64`）；
3. `./dist/qqbot-linux-amd64 version` 能跑起来，且 `checksums.txt` 覆盖两个架构。

**产物命名改一处要改三处**：`Makefile`、`install.sh`（拼下载 URL）、`release.yml`（上传清单）。
`qqbot-linux-amd64` / `qqbot-linux-arm64` / `checksums.txt`。

手动触发（`workflow_dispatch`）可以只构建不发布，用来验证 workflow 本身。

## 8. 安装与部署原理

`install.sh` 只做三件事：准备 Docker → 生成配置与密钥 → 构建并启动。
域名、证书、反代不在范围内。

```
preflight      架构 / 内存(<1.8G 警告) / 磁盘(≥8G) / swap
ensure_docker  已有就复用（1Panel 装过的也算），没有就问要不要跑 get.docker.com
gen_config     etc/env（0600，幂等）+ etc/qqbot.toml + compose.yaml + 目录属主对齐
install_src    tar 同步源码到 $DIR/src（排除 .git/bin/dist/.devroot/*.db）
fetch_binary   下载 + sha256 校验 → 成功则 QQBOT_DOCKERFILE=Dockerfile.runtime
build_and_up   docker compose build → up -d → 轮询 /healthz（最多 120s）
install_cli    deploy/qqbotctl → /usr/local/bin/qqbot
```

### 目录布局（ADR-014）

```
/opt/qqbot/
├── compose.yaml      # 从 deploy/ 拷入，每次安装覆盖
├── etc/
│   ├── env           # 密钥与构建参数（0600）
│   └── qqbot.toml    # 引导配置（已存在则不覆盖）
├── src/              # 源码快照，docker build 的 context（可随时重建）
├── data/
│   ├── qqbot/        # SQLite，uid 10001
│   └── napcat/       # QQ 登录态与配置，uid 1000
└── backup/           # qqbot backup 产物，只留最近 7 份
```

`data/` 和 `etc/` 不能删，`src/` 和 `compose.yaml` 随时可重建。
属主必须与容器内 uid 一致，否则 SQLite 建不了库、NapCat 写不进配置——
`install.sh` 和 `qqbot restore` 都会重新 `chown`。

### `etc/env` 的键

| 键 | 谁用 | 说明 |
| --- | --- | --- |
| `QQBOT_SECRET_KEY` | 二进制 | 加密主密钥，**幂等，重装不换** |
| `WEBUI_TOKEN` | compose → NapCat | WebUI 登录 Token |
| `NAPCAT_TAG` | compose | NapCat 镜像 tag，默认 `latest` |
| `PANEL_BIND` | compose | 面板绑定地址，默认 `0.0.0.0` |
| `PANEL_PORT` | compose | 面板端口，默认 `5333`。**容器内外同一个值**：`ports` 与 `QQBOT_PANEL_LISTEN` 都从它推导 |
| `NAPCAT_WEBUI_BIND` | compose | WebUI 绑定地址，默认 `0.0.0.0` |
| `GOPROXY` | 构建 | 默认 `https://goproxy.cn,direct` |
| `QQBOT_VERSION` | 构建 | 镜像 tag，`日期-时分` |
| `QQBOT_COMMIT` / `QQBOT_BUILD_DATE` | 构建 | 写进 ldflags |
| `QQBOT_DOCKERFILE` | compose | `Dockerfile` 或 `Dockerfile.runtime` |
| `QQBOT_BUILD_MODE` | 展示 | `source` / `prebuilt`，`qqbot status` 会打印 |

写入分两种语义：`ensure_kv` 幂等（已有就保留，用于密钥），
`env_set` 强制覆盖（每次构建都该刷新，用于版本号）。

### 预编译路径的判定（ADR-015）

```
下载 qqbot-linux-<arch> + checksums.txt
  → 从 checksums.txt 取本架构的 sha256
  → 比对本地文件的 sha256
  → 一致才 install 到 src/qqbot.prebuilt，写 QQBOT_DOCKERFILE=Dockerfile.runtime
```

任何一步失败都**静默回退源码构建**，不中断安装。回退时三件事一起做：
改 Dockerfile、改 `QQBOT_BUILD_MODE`、删掉残留的 `qqbot.prebuilt`
（不删的话它会一直躺在构建上下文里，12MB，下次容易搞混）。

`QQBOT_BINARY_BASE` 可指向自建镜像站，目录结构就是 Release 的 assets 平铺。

### 幂等性

- `etc/env` 已存在 → 沿用，密钥不重新生成；
- `etc/qqbot.toml` 已存在 → 不覆盖（避免冲掉用户改过的监听地址）；
- `compose.yaml` → 每次覆盖（它是项目资产，不是用户配置）；
- `PANEL_BIND` → 只有显式传 `--panel-bind` 才改，重装不会悄悄改监听范围；
- `PANEL_PORT` → 同上，`ensure_kv` 语义，已存在就保留。

## 9. 运维命令（`deploy/qqbotctl`）

刻意做得很薄：只是 `docker compose` 的包装，编排逻辑全在 `compose.yaml` 里，避免两处状态。

| 命令 | 实现要点 |
| --- | --- |
| `status` | `dc ps` + `/healthz` + 镜像来源 + `docker stats` + `free -m` |
| `url` | 按 `PANEL_BIND` 拼地址，公网 IP 靠外部服务猜（网卡上是内网地址） |
| `logs [-f] [服务]` | `dc logs --tail=200`，服务名 `qqbot` / `napcat` |
| `upgrade [--src]` | 同步源码 → 版本号改 `日期-时分` → **强制源码构建** → 失败自动 `rollback` |
| `rollback <tag>` | 只换 `QQBOT_VERSION` 再 `up -d`，不动数据 |
| `backup` | **先停容器**再打包 `data/qqbot` + `etc`（SQLite 用 WAL，热拷会不一致），只留 7 份 |
| `restore` | `down` → 解包 → 重新 `chown` → `up` |
| `reset-password` | 停容器 → 用同一镜像起一次性容器改库 → 启容器（宿主不需要 sqlite3） |
| `tunnel` | 只打印 SSH 隧道命令，不真的建隧道 |
| `uninstall [--purge]` | `down` + 删 `/usr/local/bin/qqbot`；`--purge` 才删 `data/` |

三个容易踩的实现细节：

1. **`upgrade` 一律走源码构建**，即使安装时是预编译。旧二进制配新源码的前端资源会出现
   "面板显示旧版、日志报新版本"的错位。要快速路径就 `git pull` 后重跑 `install.sh`。
2. **升级后自更新 CLI** 用 `mv` 原子替换（`install` 到 `.qqbot.new` 再 `mv -f`），
   不直接覆盖：当前脚本正被 bash 读取，覆盖同一文件可能让解释器读到半新半旧的内容。
3. **`reset-password` 的挂载点是 `/opt/qqbot/data`**，不是 `.../data/qqbot`。
   容器内 `data_dir` 是 `/opt/qqbot/data`，库在它下一层。

## 10. 排障

按"从近到远"的顺序，别一上来就怀疑代码。

### 容器起不来

```bash
cd /opt/qqbot && docker compose logs --tail=80 qqbot
qqbot status
```

| 日志 | 原因 |
| --- | --- |
| `缺少 QQBOT_SECRET_KEY` | `etc/env` 丢了或没注入。补一行 64 位十六进制，或重跑 `install.sh` |
| `配置文件不存在` | `etc/qqbot.toml` 没挂上，检查 `compose.yaml` 的 volumes |
| `unable to open database file` | `data/qqbot` 属主不对（要 10001） |
| `panic: ... address already in use` | 5333 被占，`ss -ltnp \| grep 5333`；改 `etc/env` 的 `PANEL_PORT` 即可换端口 |

### 面板能开但登录不上

`qqbot reset-password`（默认同时关 TOTP）。密码是 argon2id 哈希，取不回明文。
登录连续失败 10 次会锁 15 分钟——重启容器可立刻解除（计数在内存里）。

### 连不上协议端

```bash
qqbot logs -f          # 看是不是在重连循环
docker exec qqbot-napcat sh -c 'netstat -ltnp | grep 3001'
```

- `401` → NapCat 的 WS 服务端配了 Token，qqbot 这边没有（ADR-011：Token 应留空）
- `connection refused` → NapCat 还没登录成功，WebUI 扫码先
- 登录成功但 5 秒内没连上 → 看 `qqbot logs napcat`，多半是 WS 服务端没启用

### 明明有预编译产物却走了源码构建

安装日志里那一段会打印原因：

| 提示 | 处理 |
| --- | --- |
| `下载失败` | GitHub 不通，或该 tag 还没发 Release → 换 `QQBOT_BINARY_BASE` |
| `校验文件 checksums.txt 下载失败` | Release assets 不齐，三个文件都要有 |
| `sha256 不匹配` | 镜像站放的是别的项目产物，或文件被截断 |

排查完确认一下：`grep QQBOT_BUILD_MODE /opt/qqbot/etc/env`。

### 构建时 OOM

`dmesg | tail` 里能看到 `Out of memory: Killed process ... go`。
加 2G swap 再 `qqbot upgrade`；或者用预编译路径，服务器上完全不跑编译器。

### 版本错位（面板显示旧版）

`qqbot upgrade` 没走源码构建，或者镜像 tag 与 `src/` 不同步。
`qqbot status` 会打印镜像版本；`qqbot upgrade --src <目录>` 重建一次。

## 11. 踩坑清单

按时间顺序，每条都是真踩过的。改相关代码前扫一眼。

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| clone 后编译报 `pattern all:dist: no matching files found` | `web/dist/` 被 gitignore | 前端是源码，必须提交（ADR-003） |
| `sudo ./install.sh` 报 `Permission denied` | 脚本没有 x 位（Windows 上 `chmod` 不进仓库） | `git update-index --chmod=+x install.sh deploy/qqbotctl` |
| `bad interpreter: /usr/bin/env bash^M` | CRLF 换行 | `.gitattributes` 钉 `eol=lf` |
| 预编译路径永远不生效，静默回退 | Git Bash 的 `sha256sum` 行首加 `\` 转义，取 `$1` 拿到带反斜杠的串 | `hex_of()` 只留十六进制 + 长度必须 64 |
| `checksums.txt` 解析不到条目 | Windows 下格式是 `hash *文件名` | awk 里 `sub(/^\*/,"",name)` |
| `no such table: settings` | 照旧文档直接 `sqlite3` 改表 | 表是 `app_settings`，整份配置在一个 `json` 列里；用 `qqbot reset-password` |
| 改业务代码后镜像不更新 | `tar --exclude=dist` 把 `web/dist` 一起排掉了 | 写 `--exclude=./dist`，前缀不能省 |
| 国内构建 `go mod download` 超时 | `ARG GOPROXY` 声明在使用它的 `RUN` 之后，被静默丢弃 | ARG 必须在使用前声明 |
| 面板能开、调模型报 x509 | alpine 缺 `ca-certificates` | 运行段 `apk add ca-certificates` |
| NapCat 随机崩渲染进程 | `/dev/shm` 默认 64MB | compose 里 `shm_size: 256m` |
| SQLite 写不进去 | 数据目录属主与容器 uid 不一致 | `chown -R 10001:10001 data/qqbot` |
