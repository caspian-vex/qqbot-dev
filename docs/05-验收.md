## 验收中发现并修掉的问题

这些都是**真机上才暴露**的，不是推测：

### 1. OneBot Token 会导致首次部署必然连不上（严重）

`install.sh` 原本生成 `QQBOT_ONEBOT_TOKEN` 并注入 qqbot，期望 NapCat 侧填同一个值。
查 NapCat 官方文档确认：`WEBUI_TOKEN` 与 `MODE` **只在配置缺失时初始化**，
`MODE=ws` 生成的 WebSocket 服务端**不带 token**。qqbot 带 token 去连 → 握手 401。

修复：默认两边都不设 token（ADR-011）。3001 只绑 127.0.0.1，留空是可接受的默认姿态。

### 2. 容器 uid 与数据目录属主不一致（严重）

宿主目录由 root 创建（0755），容器内以 uid 10001 运行 → 写 SQLite 直接 permission denied。
报错发生在容器日志里，很容易被当成"启动慢"。

修复：`install.sh` 在启动前 `chown` 数据目录（qqbot 10001 / napcat 1000）。

### 3. `.dockerignore` 把前端源码排掉了（严重）

模式写成 `dist`（不带斜杠）会匹配**任意层级**的同名目录，`web/dist` 被一起排除，
编译报 `pattern all:dist: no matching files found`。
同样的坑在 `tar --exclude` 上出现过一次（必须写 `--exclude=./dist`）。

修复：`.dockerignore` 全部改成 `/dist` 这种绝对形式。

### 4. Dockerfile 里 `GOPROXY` 构建参数未声明

`RUN` 里用了 `${GOPROXY}` 但前面没有 `ARG GOPROXY`，compose 传进来的值被静默丢弃，
回落到 `proxy.golang.org`——国内机器上这一步会超时。

修复：在第一个 `RUN` 之前声明 `ARG GOPROXY`。

### 5. 列表接口返回 `null` 而不是 `[]`

`/api/personas`、`/api/sessions`、`/api/audit` 在空数据时返回 `"items":null`。
Go 的 nil 切片编码成 JSON 是 `null`。前端恰好有 `|| []` 兜底所以没崩，但契约是错的。

修复：统一过 `nonNil()`。

### 6. `PUT /api/settings` 不支持部分更新

从零值结构体解码，只传 `{"bot":{...}}` 会因为 `llm.base_url` 为空报"模型地址不能为空"。

修复：在**当前配置的副本**上解码，缺省字段保持原值。

### 7. `qqbot status` 的面板地址拼接错误

`echo "http://127.0.0.1:$(A && echo B || echo C):8080"` 会拼出 `http://127.0.0.1:<本机IP>:8080`。

修复：改用 `case` 分支返回完整 URL。

### 8. `PlainText()` 把 CQ 码当正文（mock 联调时抓到）

消息只有 @ 段没有文本段时，回退到 `raw_message`，而 NapCat 的 `raw_message` 是 CQ 码，
模型收到的用户消息变成 `[CQ:at,qq=10001]`。

修复：解析成功但无文本段时返回空串，只有 `message` 字段整体缺失才回退。

### 9. 文档里的密码重置 SQL 是错的

`docs/02` 第 6 节原本让人用 `sqlite3` 改 `settings` 表，
但实际表是 `app_settings(id, json)`，整份配置序列化在一个 JSON 列里。
照那个命令写会报 `no such table: settings`，而这条路径恰恰是「已经进不去面板」时才会走的，
用户没有别的手段自查。

修复：新增 `qqbot reset-password` 子命令，用镜像里的二进制改库，
不依赖宿主机装 sqlite3；文档同步改写。

### 10. `qqbot upgrade` 不更新 CLI 自身

`upgrade` 只重建镜像并重启容器，`/usr/local/bin/qqbot` 还是旧版本。
结果就是镜像里已经有新子命令，敲 `qqbot reset-password` 却报「未知命令」。

修复：`upgrade` 成功后从 `$DIR/src/deploy/qqbotctl` 同步 CLI。
用 `mv` 原子替换而不是直接覆盖——当前脚本正被 bash 读取，
覆盖同一文件可能让解释器读到半新半旧的内容。
